RK // DATA MANAGER v1
архив истории Binance Futures на диск · один раз качаем, дальше считаем локально
только скачивает и складывает — ничего не тестирует
Браузер не подходит
Нужен доступ к папке на диске (File System Access API). Его дают Chrome и Edge на компьютере.
Firefox, Safari и любой браузер на телефоне — не подойдут.

Ещё проверь, что страница открыта по https:// (github.io) или http://localhost. При открытии файла двойным щелчком (file://) доступ к папке запрещён.
Шаг 1 · Папка на диске
папка не выбрана вес API: —
Выбери пустую папку, например D:\RK_DATA. Нужно не меньше 2 ГБ свободного места.
Не клади в OneDrive или синхронизируемые «Документы» — облако будет мешать записи.
Chrome спросит разрешение — нажми «Изменение файлов», не «Просмотр».
Шаг 2 · Список монет
по данным на сегодня
отсечка сверху, по обороту
—
Берутся только бессрочные контракты к USDT в статусе торгуемых. Список пишется в universe.json вместе с оборотом на день сбора — оборот на момент каждой сделки стенд потом считает сам, из свечей.
Шаг 3 · Свечи 5m — долгая операция
400 = год с запасом
больше 2 — риск лимита
лимит Binance 2400
—
Качается помесячно. Каждый скачанный месяц сразу пишется на диск — обрыв связи, зависание или перезагрузка не отменяют сделанного, повторный запуск продолжит с первого недостающего месяца. Текущий (незакрытый) месяц перекачивается каждый раз — это нормально.
На время работы: питание в «Никогда», вкладка на переднем плане, ноутбук в розетке.
Шаг 4 · Сборка 1H из 5m
—
Сеть не нужна, считается локально. Часовые файлы — это то, что читает стенд: ~45 МБ вместо ~600 МБ, грузится мгновенно. 4H и 1D стенд соберёт из часовых уже у себя. Запускать заново после каждой докачки 5m.
Шаг 5 · Дополнительные данные
—
Финансирование — полная история с листинга, качать достаточно раз в месяц.
Метрики (открытый интерес, лонг/шорт по счетам, по позициям, тейкеры) — Binance хранит только последние 30 дней, дальше они исчезают навсегда. Каждый запуск дописывает новое к старому, так постепенно накапливается собственный архив. Жать раз в 2–3 недели, иначе появится дыра, которую уже не закрыть.

Журнал
Формат файлов на диске
RK_DATA/ ├─ manifest.json — учёт: что скачано, до какой даты, где дыры ├─ universe.json — монеты и оборот на день сбора ├─ FORMAT.txt — описание двоичного формата ├─ klines_5m/BTCUSDT/2026-01.bin — сырьё, помесячно ├─ klines_1h/BTCUSDT.bin — производное, для стенда ├─ funding/BTCUSDT.json ├─ oi/BTCUSDT.json └─ ratios/BTCUSDT.json Формат .bin (RKB1) — заголовок 32 байта, дальше подряд бары по 7 чисел float64 (little-endian): время открытия, open, high, low, close, объём в монете, объём в долларах. Заголовок: 4 байта «RKB1», uint32 версия, uint32 колонок, uint32 баров, float64 первое время, float64 последнее.
